# 需求（已确认）

## 目标

给 DeepSeek Harness 里**已经配置好**的 LLM 供应商补全模型能力参数，让官方适配器能正确
声明上下文窗口、输出上限、输入模态（含图片）与推理档位。

## 非目标

- 不实现 LLM 适配器，不发推理请求，不注册 provider 路由。
- 不替代官方模型选择器，不接管对话。
- 不修改 dsh 本体。

## 功能需求

| 编号 | 需求 | 验收 |
| --- | --- | --- |
| F1 | 读取指定配置条目（默认 `llm-pi-ai`）下某供应商的模型清单 | 设置页显示模型数量与 id |
| F2 | 从 models.dev 拉取目录并缓存 | 6 小时内重复分析不再下载；可手动刷新 |
| F3 | 把网关 id 匹配到目录条目 | 展示匹配来源（别名/精确/折叠/去前缀/去后缀）与目标 `provider/modelId` |
| F4 | 计算能力字段：`contextWindow`、`maxTokens`、`input`、`reasoningEfforts`、`name` | 预览表逐行展示，空值显示 `—` |
| F5 | 默认只填空白字段；可勾选覆盖 | 不勾选时已有值不变 |
| F6 | 逐行勾选后写入配置 | 写入后 `cordis.patch.yml` 对应条目出现新字段，界面不重启生效 |
| F7 | 未匹配模型原样保留并单列 | 列表可见，不写入 |
| F8 | 别名表：手工把网关 id 指向目录 id（P3） | 未匹配 id 可被救回 |
| F9 | 迁移旧适配器清单并停用旧插件（P4） | 模型选择器只剩官方适配器清单 |
| F11 | 名称降级匹配：ID 各规则都落空时，用显示名称（剥掉来源标注后）再匹配一次 | `qoder/qfmodel` 这类不透明 ID 也能补全能力；重命名前后解析结果一致 |
| F12 | 排序二选一：按模型前缀分组 / 按重定向后【来源】名称排序 | 两种视角可切换；名称重定向节可顺带按当前排序重排目录 |
| F10 | 名称重定向：清洗模型 ID 来源前缀在名称里的所有形态（开头 `qoder/`、旧半角 `(qoder)`），只保留末尾全角 `【qoder】`（`beichen/gpt-6-astra` → `gpt-6-astra【beichen】`） | 同名不同来源的模型在选择器里可区分；前缀只出现在末尾一处；重复应用不叠加；无前缀模型不变 |

## 非功能需求

- 零运行时依赖：宿主产物不 import 任何第三方包（`undici` 仅代理路径按需动态导入）。
- 宿主半不读写配置文件；写入只经官方 settings 服务。
- 中文优先的界面文案，英文同步维护。
- 类型检查与构建可离线复现（`npm install` 后 `npm run build`）。

## 明确不做

- `top_p` / `seed` / `presence_penalty` / `frequency_penalty` / `response_format`：
  dsh 的调用配置没有这些字段的来源。
- 助手侧图片输出：dsh 的 assistant 内容块没有图片类型。
- 多网关并存：本插件只处理"已配置的"供应商条目，不做网关管理。
- 重写用户自起的名称：名称重定向只追加来源前缀（并在重复应用时剥掉自己追加的
  同名后缀），不猜测、不翻译、不替换用户已写的内容。
