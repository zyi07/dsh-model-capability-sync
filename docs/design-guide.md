# 设计规范

原则：**简洁、直观**——一屏看完，一步一个动作。

## 布局

```
标题（intro 一句话说明本页做什么）
────────────────────────────────
[目标插件 ▾] [供应商 ▾]   共 N 个模型
[分析能力] [重新下载目录]   ☐ 覆盖已有值
────────────────────────────────
表格：☐ | 模型 ID | 匹配 | 上下文 | 输出 | 图片 | 推理档位
────────────────────────────────
[应用]
未匹配清单（可折叠的说明 + id 列表）
```

## 视觉

- 全部颜色走 shell 的 `--dsw-alias-*` 令牌，浅色/深色主题自动适配，不写死颜色值。
- 复用官方设置页的控件形态：圆角 8px 输入框、圆角 6px 按钮、12px 说明文字。
- 「图片」支持时用主色描边徽章（`.cs-badge--image`），纯文本用弱化灰，避免整表高亮。
- 表格数字右对齐等宽显示（`font-variant-numeric: tabular-nums`），便于纵向对比。

## 交互

| 动作 | 反馈 |
| --- | --- |
| 分析中 | 按钮文字变「正在匹配…」并禁用，避免重复点击 |
| 写入中 | 按钮文字变「正在写入…」并禁用 |
| 写入成功 | 顶部一行「已写入 N 个模型」，表格保留以便复核 |
| 无匹配 | 不写任何东西，直接列出未匹配 id |
| 未勾选任何行 | 点应用只提示「没有选中任何模型」，不发请求 |
| 出错 | 红色一行错误原文，不吞异常 |

## 文案

- 中文优先，英文逐键对应（`src/client/locale.ts`）。
- 动词开头、句子短：「分析能力」「重新下载目录」「应用」。
- 说明性文字放 `title` 或小号灰字，不打断主流程。
- 专有名词不翻译：`models.dev`、`llm-pi-ai`、模型 id。

## 可访问性

- 每个复选框有 `aria-label`（模型 id 或「全选」）。
- 纯图标/无文字控件必须带标签；本页只用一个「全选」复选框，已带标签。
- 颜色不是唯一信息载体：「图片」同时有文字「支持 / 纯文本」。
